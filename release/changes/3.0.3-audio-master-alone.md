# 3.0.3 audio-master-alone release preparation

Version `3.0.3` is version 3.0.2 (`main` at `c05e511`, which is 3.0.1 plus the welcome page, PR322) plus the audio-master inversion alone (PR361, merge `9068ad3`). The audio-master change is restored by reverting `f74daec`, the revert that took PR361 off `main` for the highlight-only release, and the branch is then merged with `main` at `c05e511`. Outside `package.json`, `package-lock.json`, `CHANGELOG.md`, this note and the release-closure pins, the tree differs from `main` at `c05e511` only in the ten files of PR361.

This change was first prepared as 3.0.2 on top of 3.0.1. The welcome page release took that number and reached `main` first, so this change is renumbered 3.0.3 and placed on top of it. When this note was written, production served 3.0.1 (`628a898`) and 3.0.2 had not been promoted to production.

## Why

PR361 was reverted only so that 3.0.1 could carry the highlight change alone. Of the three merges reverted for that release it is the one that touches no content pack, server or service worker file. The Spanish Luke recompile (PR356) replaces published passage revisions, and a saved copy whose revision the server no longer holds is revoked by the service worker (defect D1). Restoring PR361 by itself lets audio-master reach DEV while a promotion from `main` still replaces no published passage revision.

## What is in it

The audio-master change as described in [2026-11-09-audio-master.md](2026-11-09-audio-master.md): a recorded guide stage opens one media session for a run of consecutive same-file clips, the pages turn by the player clock, both pause when the audio pauses, and Next, Back, swipes and the Overview seek the running session to the chosen screen. The planner keeps the identity, source-pin, mapping and verified-timing checks; a run that cannot be planned plays each screen's clip on its own as before.

The revert conflicts only in the generated release-closure pins, which are regenerated. The merge with `main` conflicts only in `CHANGELOG.md`, where both entries are kept, and in the same pins file. Eight of PR361's ten files are the same blobs as at `9068ad3`. `apps/web/src/App.svelte` differs from `9068ad3` only where PR356's lines are absent. `apps/web/tests/continuous-reading.spec.js` differs from `9068ad3` only in the clamped-highlight test correction that reached `main` with the welcome page (PR322); the merge applied it without conflict.

## Pack safety

`apps/web/public/content` and `server/` are the same git objects as on the `production` branch (`628a898`) and on `main` at `c05e511`. `apps/web/public/sw.js` is the same git object as on `main` at `c05e511`; against production it differs only in the one line of the welcome page release, which adds `/welcome` to the path families the worker hands straight to the network. The generated worker snapshot (`server/faces/worker/generated/snapshot.json`) has the same sha256 as a build of production: `ceecf730edbff91bee731715b2c975f302f57365b6c3fa43873e52bf48b72449`. No published passage revision is replaced and this version changes no service worker source line. The app bundle is new.

## Not in it

PR356 (Spanish Luke honest-text recompile, which also carried the 3.1.0 release prep) and PR360 (saved-pack worker change) stay reverted on `main`. Defect D1 is not fixed. Draft PR364, which restores all three reverted merges together, stays a draft; after this version it needs a rebase and then restores PR356 and PR360 only.

## Limits

This version is held from production until a physical iPhone pass. The evidence so far is synthetic-clock tests, in which the tests drive the player clock, and one desktop Chromium run in which English Mark 1:1–13 opened and played; neither certifies acoustic synchronization on a device. That Chromium run was made on an earlier tree with the same audio code, before the merge with `main`. No phone, iOS Safari or installed home-screen app has been used, and no upgrade from production's build or from a 3.0.2 build to this one has been rehearsed. Each environment still requires independent review, required checks and exact-commit post-deploy evidence under `RELEASING.md`. This note does not merge or deploy anything.
