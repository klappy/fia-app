# Whole-book saving containment — 3.0.0-alpha.19

Release metadata for the increment already merged through `1c144cb637529bbb7472de1fc5265c3b3154b8c9` (PR277 and PR279). This release preparation is metadata only; it carries runtime behavior from PR277 and PR279 only.

- Client containment: the updated Downloads sheet marks whole-book saving temporarily unavailable; per-passage saving remains available. See [whole-book saving](whole-book-download.md).
- Worker guard: the worker refuses to replace a verified executable Saved snapshot with a base or snapshot-less save, PR277.
- Offline approved audio: verified Saved approved audio now plays offline; canonical refusals fail closed, PR279.

Known limits remain explicit: first saves without a prior executable Saved snapshot are outside the guard; already-loaded old clients and offline workers must update before the guard applies to them; snapshots already replaced are not recovered; and a rejected old-client save can leave an unreferenced `-repair` artifact cache, which is known storage overhead with a follow-up queued. The alpha18 release history is not rewritten.

Known PR279 limits: 501/505/52x/530 responses can retire Saved instead of being treated as transient; a pause during activation can leave the passage unsaved until another Save succeeds; offline approved audio needs verified core files; and each audio Save downloads the audio twice.

The alpha18 production baseline does not qualify this bumped candidate. The release owner must collect fresh exact-candidate review, required checks and DEV → staging → production deployment proofs for this candidate through the existing sequential release process.
