# Summit candidate — 3.0.0-alpha.21

Release metadata for the increment merged on main after alpha.20 (`1d0331c`), through `f779516b5ff798a7c3ba98b16191eafdc4f1bf59` (PR335, including PR324 and PR338). This release preparation is metadata only and adds no runtime behavior of its own. Its scope must be re-gathered, and the closure re-pinned, if more changes land on main before it merges.

Visible changes:
- **Persistent audio and script presentation** (PR324): a persistent player per distinct audio file supports reuse and seeking; the controller owns the script, sidecar word map and auto-advance. This also carries the one-card presentation and word-highlight captions from timing sidecars for Mark 1:1–13.
- **Unavailable picture or map** (PR318 train N, with PR321): the step's own guide words stay on the stage as a labelled, keyboard-focusable scroll region. A bounded status card reads "This image is unavailable here. You can continue without it." ("map" for maps). While the device check runs, the card stays silent. Captions read "FIA Images · CC BY-SA 4.0" / "FIA Maps · CC BY-SA 4.0". See [unavailable-visual-stage](unavailable-visual-stage.md).
- **Unavailable-card layout** (PR335): the card remains non-scrolling, preserves its reviewed aspect ratio when space allows, and uses compact short-stage layouts, including Cancel/Try again controls. See [card layout and limits](unavailable-visual-card-followup.md).
- **Trusted Mark placement and visual-capable client** (PR283, PR287 via PR318): Mark 1:14–20 S02-U008 receives the reviewed trusted placement. The client accepts the closed visual contract and keeps Saved state when an older server refuses `execution=2`. No visual bytes are published.
- **Stage notices** (PR330): the narration-blocked and offline notices grow the top band instead of covering the stage title, credit or first guide line.
- **Passage card names** (PR326): each Passages card's button is named `Open passage: <title>` or `Resume passage: <title>`. The visible label is unchanged.
- **Guide audio tail** (PR333, refined by PR324): ranged guide clips play the same Opus packets as WebM, and each clip's end extends by up to 0.25 s without reaching the next clip's speech.
- **Saving** (PR323): Saved-snapshot artifacts are verified by a pool of up to four fetches. Saved is reported only after every artifact verifies. The live-listening harness waits up to 120 s for a cold save.

No user-visible change:
- PR338 repairs listening evidence for the deterministic Ogg-to-WebM remux: exact derived-byte identity is checked rather than treating an intentional container change as wrong Scripture media. It does not change app playback.
- PR327 adds a language-aware transcript normaliser in the audio-transcript pipeline. English output is byte-identical.
- PR328 and PR329 add Spanish coverage detection and machine-translation toggle plumbing in the data layer only. It defaults to OFF, no provider is wired, and nothing imports it at runtime.
- PR332 updates the scroll-follow spec and removes unused CSS.
- PR325 changes repository agent settings (`.claude/`), not the app.

Known gaps:
- Mark 1:1–13 verses 4, 6, 7, 8 and 10 use word timings from an automatic recognition pass, shifted +140 ms onto the reviewed clock. Those five verses' timings are **not human-reviewed**; the other reviewed verses are unchanged. See the Nov 5 update in [word-timing scope](scripture-word-timing-and-highlight.md).
- No image or map bytes are delivered.
- On short landscape stages a raised notice can leave no visible step words until dismissal (PR335). The reviewed artifact contains 844×390 rather than a separate 390×844 unavailable-state capture; the interactive regression injects a button rather than exercising the complete asynchronous loading/retry journey.
- The Spanish `[ES needed]` label and the opt-in machine-translation control are not shipped in the UI.
- Mark 1:14–20 lacks the gel/timed-turn sidecar and uses the fallback.
- ASR ranges beyond the span and zero-match highlighting, playback-clock mapping, reserved-pool growth, saved identity/passage-file handling, and blob-cache bounds remain follow-up work from PR324.
- The guide-tail fix is not verified on an iPhone.
- Physical-device, audible and whole-corpus acceptance are not part of this release.
