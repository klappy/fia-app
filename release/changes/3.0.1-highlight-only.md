# 3.0.1 highlight-only release preparation

Version `3.0.1` is production 3.0.0 (`56a000e`) plus the highlight change alone (PR354, merge `14bf935`). It is reached on `main` by reverting, newest first, merges `9068ad3` (PR361, audio-master r2), `f528849` (PR360, saved-pack worker change) and `cab28aa` (PR356, Spanish Luke honest-text recompile, which also carried the 3.1.0 release prep). Outside `package.json`, `package-lock.json`, `CHANGELOG.md`, this note and the release-closure pins, the tree equals `14bf935`.

## Why

The 3.1.0 promotion (PR359) replaces the published revision of 262 of 330 passages. A server that no longer holds a saved revision answers the pinned read with HTTP 404, and the service worker then revokes the saved copy (defect D1). PR360 does not change that. The highlight change alone differs from production in 26 files, none under the content packs, the server or the service worker, so no passage revision moves and the worker is production's.

## What is in it

The highlight change as described in [2026-11-09-highlight-always.md](2026-11-09-highlight-always.md): highlighting at the closest match with a data-attribute timing tier, the regenerated S01 activity maps, the once-per-session unavailable-recording notice, the deleted step-resources footer code and the corrected manifest passage counts.

## Reverted work returns

The reverted merges return to `main` by reverting these reverts right after the staging leg merges. Between this release landing on `main` and that re-land, DEV runs without audio-master and without the Spanish Luke recompile.

## Limits

Human review of the regenerated S01 timings and a device pass of the gel at the approximate tier are owed. Upgrade rehearsals so far used local builds, text-only saves and no phone or iOS Safari. Merging needs the captain's recorded ruling for this option; each environment still requires independent review, required checks and exact-commit post-deploy evidence under `RELEASING.md`. This note does not merge or deploy anything.
