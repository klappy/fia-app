# 3.0.0-alpha.12 — Media tap and swipe intent

Inline images previously opened on pointer-down, before tap versus swipe intent was known, while all media surfaces rejected passage swipes. Resting inline images/maps and video surfaces without exposed controls now use the existing Next/Back actions for a qualified horizontal swipe. A completed tap opens the visual; drag, pinch, cancellation and stale asset transitions do not. Compatibility-click suppression is bounded and restricted to its original target.

Normal touch capture release after pointer-up preserves a completed tap. Native video controls, fullscreen/zoomed views, vertical scrolling, system edges and disabled navigation remain excluded. No CSS, spacing, source content, delivery, audio or native-video ownership changes.

Validation: the final full suite passed102Node and113Vitest checks; the build and seven release-envelope checks passed. Actual desktop Chrome evidence includes five initially passing gesture cases and the previously failing native-tap case passing after the fix. Earlier failed evidence is retained. Existing strict visual parity remains required; no baseline refresh or physical-iPhone success claim. Recipe: cookbook135, merge55458aa0f058211df02b75fb3751f2356cf7e42d.

The app release is queued behind the service train; this note does not claim deployment.
