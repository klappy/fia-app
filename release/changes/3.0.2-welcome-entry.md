# 3.0.2 welcome entry release preparation

Version `3.0.2` is production 3.0.1 (`628a898`) plus the welcome page alone (PR322). Outside `package.json`, `package-lock.json`, `CHANGELOG.md`, this note and the release-closure pins, the tree equals PR322's head `ba8bf07`, which differs from production in 12 files.

## Why

The welcome page travels on its own train so that its promotion carries nothing else: neither the audio-master inversion (PR361), which waits on a physical-device pass, nor the Spanish Luke recompile (PR356), which replaces published passage revisions. PR322 carries no version bump and no `CHANGELOG.md` entry; a promoted tree needs both, and this preparation adds them without moving PR322's checked head.

## What is in it

The welcome entry as described in [fia-welcome-entry.md](fia-welcome-entry.md):

- Five static files under `apps/web/public/welcome/`: the page, its stylesheet, one font, the FIA lockup and one portrait guide preview image. The page explains FIA and has one primary Open FIA action, which links to `https://fiaguide.app/` from every environment. The app root, the installed-app entry, deep links and the QR target are unchanged. No process video is included.
- One service worker line: `/welcome` joins `/v1`, `/mcp`, `/docs` and `/content/source` in the list of path families the worker hands straight to the network. Against production, `apps/web/public/sw.js` differs in that one line.
- One build filter: `scripts/finalize-build.mjs` leaves `dist/welcome` out of the file list behind the downloadable manifests, so the page is in no saved passage or legacy pack and a change to it does not change those manifests.
- Tests for the worker line and the filter (`apps/web/tests/offline.test.js`, `tests/web-shell/download-build.test.js`), and one inherited test correction that rides with PR322 (`apps/web/tests/continuous-reading.spec.js`).

## What does not change

No file under `apps/web/public/content`, `server` or `apps/web/src` differs from production, so no published passage revision moves and the built worker snapshot (`server/faces/worker/generated/snapshot.json`) has production's bytes, sha256 `ceecf730edbff91bee731715b2c975f302f57365b6c3fa43873e52bf48b72449`.

PR356, PR360 and PR361 stay reverted on `main`. The saved-copy defect (D1: the service worker revokes a saved copy whose revision the server no longer holds) is not fixed by this version.

## Limits

Not shown: the page on a phone, in iOS Safari or from an installed home-screen app; and the first visit to `/welcome/` on a device that already runs the app's earlier service worker. That worker has no `/welcome` entry; such a device can update from the app root and then reopen the page, and automatic recovery of that first visit is not promised. An upgrade rehearsal from production's build to this tree with saved passages is a condition of the production leg and is recorded with PR322, not in this note. Each environment still requires independent review, required checks and exact-commit post-deploy evidence under `RELEASING.md`. This note does not merge or deploy anything.
