# Mark catalog and presentations through the shared read API

The existing read_pack/read_artifact operations now expose the same136 accepted English and Spanish Mark presentations as the browser catalog. Read pack fia-mark-catalog to discover the byte-exact schemaVersion1 catalog, then request each descriptor's exact source ID and revision. HTTP and MCP return equivalent records and immutable bytes. The original three accepted records and their artifact identities remain unchanged.

The Worker keeps reviewed metadata and retrieves only a requested allowlisted static JSON artifact through the existing ASSETS binding. Status, MIME, UTF-8, length and SHA256 are checked before delivery, with a1MiB artifact ceiling. Missing or corrupted content stays unavailable. Unexpected storage faults remain internal errors in both faces. No external fetching, paid preparation, write endpoint or new service is added.

The browser UI, source text, per-passage progress, manual resource-download policy and existing recordings are unchanged. Source-referenced media remains metadata; this API does not prepare it. Conservative instruction diagnostics remain visible and full automatic guide interpretation is not claimed. This release contains no audio job fixtures or local audio generation.

Validation includes four cross-language HTTP/MCP samples before all136, catalog and original-record byte identity, lazy-path isolation, integrity/limit/error tests, packaged Worker checks and independent review. Ordinary CI and the sequential DEV→staging→production train remain required. This note describes a candidate until those stages complete; external-host interoperability remains unverified. Automation stays paused.
