# 3.0.0-alpha.3 — Online destinations with saved passages

An installed passage previously caused every same-origin document navigation to return its cached app shell. Explicit status, help, provenance or API destinations could therefore display the app instead of their own response.

The browser worker now sends reserved /v1 and /mcp families, existing /docs and /content/source families, status routes and version.json to the network before installed-pack handling. Status/version remain no-store. Other online responses keep their status, headers and body; network failure never substitutes installed or shell-cache HTML. Matching uses exact roots or slash descendants, preserving similarly prefixed app routes.

Root and session navigation remain pinned to the installed revision, including new-client revision bindings. Download verification, atomic activation, resume/remove, media ranges, user progress/preferences and the approved interface are unchanged. This does not add offline help/API access, switch the client to API content, or change content/media authority.

Cookbook acceptance: installed-pack-navigation-v1 at 02d5361d15e5cce3fa2a74c3d2f98f26579f3e93. The two new failing regressions reproduced the pre-fix response substitution and suppressed network failure. All thirteen focused offline tests pass after correction, including active and shell-only failure scenarios and preserved session pinning. This is worker-source VM evidence; actual browser/deployment gates remain separate. Existing UI source identity and release checks continue; no new device or acoustic claim.

The sole release operator uses the existing reviewed DEV → staging → production Git train, exact deployed version/commit and relevant smoke/upgrade/API checks. Rollback is a reviewed revert/backflow to the preceding accepted alpha.2 deployment. No direct deployment, new infrastructure, paid work or feedback collection is introduced.
