# 3.1.3: the video control's label carries the missing-Spanish marker

Version `3.1.3` is 3.1.2 plus two changes. On the media stage, `apps/web/src/components/MediaStage.svelte`, the `<video>` element's `aria-label` goes through `displayTitle` (`apps/web/src/lib/spanish-coverage.js`) instead of printing the bare asset title. On the guide page, `apps/web/src/App.svelte`, the blocked notice stays spent after its first card is left (PR381, Codex P2 on PR365; see [Blocked notice stays spent](#blocked-notice-stays-spent) below). No Spanish text is added or changed. No content pack, server or service worker file changes: nothing under `apps/web/public/content` or `server/`, and not `apps/web/public/sw.js` or `apps/web/src/lib/spanish-coverage.js`.

## Why

A Spanish pack records, per picture, map, video and key term, whether its title is Spanish or the English one shown in its place. `titleMarker` and `displayTitle` turn that state into the plain-text marker `[ES needed]`, and every other surface that prints an asset title goes through one of them: the heading and caption above the video, and the full-screen dialog's label in the same file. The video control's own accessible name was the bare English title, so a screen reader landing on the control got no sign that the title is a fallback.

The gap was found by reading code (an automated code review comment on pull request 368 and the traced reply under it). It has not been checked with any screen reader.

## What changes

One expression: `aria-label={asset.title}` becomes `aria-label={displayTitle(asset)}`. For a video whose state is `english-fallback` or `missing`, the label reads `<title> [ES needed]`; with no state (English packs) or the state `present`, it reads the title alone, as before. The marker's wording, the helpers and the compiler are unchanged. The label still names the same asset as before.

Four test cases cover it in `apps/web/tests/spanish-marker-surfaces.spec.js`, rendering `MediaStage` directly with an invented English-placeholder fixture: `english-fallback` and `missing` give the `<video>` element the label with the marker (and, for `english-fallback`, the heading reads the same); no state and `present` keep the bare title and print no marker anywhere.

## Blocked notice stays spent

PR381 (Codex P2 on PR365). In a pack with no guide recordings, the notice "This recording is unavailable. You can continue." was meant to show once per session (PR354), but `blockedNoticeSpent` held only while the current card differed from the one that raised it, so going back to that card raised it again (the re-show accepted as a risk in 3.1.1). A new effect in `apps/web/src/App.svelte` marks the shown record as left once the card changes, and `blockedNoticeSpent` also holds when it is marked left, for the same pack revision only. `reset()` (Restart passage) still clears the record, so a restarted session gets its one notice again.

One test in `apps/web/tests/blocked-notice-once.spec.js` covers it: the notice shows on the first card, is gone on the next card, stays gone back on the first card, and shows again after Restart passage. It has not been checked on a device.

## Not fixed, not shown

- The control with any screen reader, and how a screen reader speaks the marker. Whether each browser takes a `<video>` element's `aria-label` as its name while native controls are hidden was not checked.
- The caption's missing space before the marker (`Clip[ES needed]` in a test render) is not changed here.
- While a video plays in place over a picture, the label names the picture on the stage, not the video; this release does not change that.
