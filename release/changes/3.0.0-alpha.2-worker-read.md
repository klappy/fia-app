Adds a Fetch adapter to the existing environment Workers, preserving their application assets and Git deployment train. MCP supports the pinned 2025-06-18 protocol and read_pack/read_artifact tools; no session/SSE or external-host compatibility is claimed.

## Verification and limits

The candidate is checked with actual packaged workerd requests, shared HTTP/MCP equivalence, exact accepted artifact hashes, body/origin refusals, restart identity, and the real static-assets router. Build tests verify all154 media bytes, unchanged UI source hashes, reserved-route handling and exclusion of API data from offline downloads. Existing application CI and independent review remain release gates. Dry-run packaging proves build compatibility, not live availability.

DEV → staging → production must each verify the exact new deployed SHA/version, existing app smoke and real HTTP/MCP artifact reads before promotion or delivery claims. There is no new infrastructure or direct deployment. Rollback remains a reviewed promotion revert with verified deployed identity and backflow. Other passages/languages, dynamic catalogs, external LLM host integration, client API loading, native/device and acoustic validation remain outside this increment.
