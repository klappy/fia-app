# Truthful passage switch (R1)

Repairs red DEV (`3d3b1d2`): opening Mark 1:14–20 showed "The server catalog is invalid.", a saved refused passage showed that toast on every launch, and returning to Mark 1:1–13 failed with a 500.

The service worker now passes the server's answer for `/v1/packs` and `/v1/artifacts` to the page unchanged: status, content type and JSON body. It no longer rewrites a non-200 into a plain-text 409. Verification still decides whether a saved snapshot stays usable. Only a failed fetch or a transient server status may use a verified saved snapshot. "The server catalog is invalid." is now reserved for a malformed record.

The Passages sheet shows the truth next to the card that was opened. Open is disabled and `aria-busy` while its request is pending. An unavailable or refused passage keeps the sheet open, says so in the card, stops claiming recordings on request, and leaves the current passage, its playback and its saved progress unchanged. The reading screen gets a notice only if the sheet was closed before the answer arrived. A saved passage that cannot be restored at launch leaves the default passage open with one short notice and clears the saved key, so later launches are quiet. A missing connection keeps the key.

Server: a publication validated under a superseded execution policy (the policy hash includes the approved-audio proof index, which PR #189 added) no longer shadows its base record. The current read serves the base with its preparation demand, so an explicit Open republishes under the current policy; identical bytes replace only a row that no longer verifies. The approved original Mark 1:1–13 presentation is no longer offered, or admitted for, a preparation it cannot fulfil. Any resolver or projector refusal is a typed `blocked` answer with its code (HTTP 409), never a 500.

The same rule covers the projector recipe change from #190 (`fia-server-source-action-projector@1` → `@2`). Job and publication rows written under `@1` now read as an `execution-job-policy` mismatch. The base is served, an explicit Open re-prepares under `@2`, and the client opens the passage without an error.

Dock gating during a pending switch (A7, advisory) is not included. DEV acceptance (A5, A6) must be recorded after deploy.
