# fia-easy-button-policy@2

One pure function decides the FIA easy button (primary action), what starts by itself (arrival, after narration, detour video), the pause-only viewing cue and the hold, from the compiled flow, the device settings and the runtime facts. Every client calls the same `decide()` on the same input and gets the same answer.

- **Contract (prose, rule ids, invariants, dependencies):** fia-app-cookbook `product/v3-planning/easy-button-policy/CONTRACT.md`. Plan: `work/active/2026-10-06-fia-easy-button-policy/PLAN.md`.
- **Files:** `fia-easy-button-policy@2.schema.json` (draft 2020-12, `$defs.input` / `$defs.output`, closed objects, no text fields; equal to the `SCHEMA` export, test-enforced) · `index.mjs` (`SCHEMA`, `validate`, `decide`, `causeOf`, `flowFrom`, `ACTIONS`, `CAUSE_CLASSES`; no imports, no DOM, no clock) · `fixtures/named.json` (40 hand-checked rows, every rule id) · `fixtures/generate.mjs` → `fixtures/table.json` (the declared 768-row projection, phase loading/starting/verified, not the full product) · `fixtures/parity-divergences.json` (expected: none).
- **Rules:** primary E0–E7 (executable chain) and B0–B1, B3–B16 (bundled chain; B2 retired, playbackPending joins B6), with E0/B0 verifying and E1/B1 starting as easyFace() over the verified action (`primary.verified`); arrival A1–A7 (scheduleNext :273-282); after narration F0–F2 (finishAudio :270-271); detour video D0–D1 (:344); viewing cue V0–V1 (:293 with `flow.cue.pauseOnly` in place of the phrase test). `reason` is the primary rule id; `reasons` names the rule behind each decision. Label-chain parity is against the post-R6 App.svelte (integration/2026-10-06-train @21ad2dc, #193); other line cites are against fia-app main @3d3b1d2.
- **Why @2:** CONTRACT.md "When @1 becomes @2": removing `cancel-loading` from the action enum, a new input fact a rule reads (`facts.requestStarting`) and a removed rule id (B2) each require a new major. @1 never shipped to main or the train.
- **Post-R6 (#193 R4–R6):** nothing is reserved. `verifying` is emitted on phase `loading` (R5, k0006/k0011); `starting` is emitted on phase `starting` unless narration is off outside a detour, the session is finished or a section transition shows (R4 primaryStarting). `cancel-loading` is gone: cancel never sits in the primary's slot (R4.2, proposed design detail; #193 behaviour). `facts.requestStarting` keeps preparation from owning the primary while a request start is carried (B12).
- **Cause taxonomy:** `causeOf(prev, next)` classifies an input delta for the #216 EB guard (gesture, network, status settled; media-event, scheduled-start provisional). It is data, not a runtime guard; the window and one-change-per-cause rule stay with #216.
- **Tests:** `node --test tests/contracts/*.test.mjs` (in `npm test`). Regenerate the table with `node packages/contracts/easy-button-policy/fixtures/generate.mjs`; the test fails on drift.
- **Client notes:** `facts.playbackConsent` for D1 is the consent held before the detour navigation (App.svelte:341 `hadPlaybackConsent`, read before `revokePlayback`). `afterNarration` continues narration the listener already started, so I4 (no consent, nothing starts by itself) covers arrival and detour video only — as App.svelte:270-271 does today.
