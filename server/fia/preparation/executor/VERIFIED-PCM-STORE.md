# Verified retained PCM producer

`createVerifiedPcmStore({storage,bucket,decode,verifySource,eligibility,dependencySha256,maxSamples=16000*1800,stepMs=120000})` exposes request/read/recoverInterrupted. Requests are exact `{source:{sha256,reference,bytes},pcm:{sha256,samples,sampleRate:16000,decoderSha256}}`; source reference is canonical originals/sha256/<sha>.mp3. Decoder identity, exact PCM/source pins and dependency policy are durable demand identity. Source length is bounded16MiB; PCM is at most28,800,000mono float32 samples (115,200,000bytes).

The trusted decoder port receives `(request,{signal})` and returns `{receipt:{sourceSha256,pcmSha256,totalSamples,sampleRate,decoderSha256},stream,dispose}`. It must bind actual retained source decoding and contain no unapproved source fetch. `verifySource(source,{signal})` is a read-only retained-source/provenance check returning the exact descriptor; it runs cold and warm. Eligibility must synchronously return exactly true. These are trusted source/decoder execution boundaries, not caller self-attestation.

A durable claim precedes decoding or writes. The producer validates at most64KiB input chunks, incrementally hashes/counts them and checks every float32 sample, including samples split across chunks. It streams through a native FixedLengthStream into a create-only R2 object `preparation/pcm/<sha>.f32`; no whole PCM buffer is assembled. One chunk plus a maximum3-byte float carry is application memory; R2/runtime buffering is unmeasured. Optional makeStream exists for tests only; real workerd uses native FixedLengthStream.

Readback rehashes retained bytes and requires exact canonical immutable receipt `preparation/pcm-receipts/<demandSHA>.json`, bound to source, decoder, PCM, policy and attempt. A completed durable row and matching receipt are both required for warm reuse. Orphan objects refuse rather than acquire trust from content hash alone. Concurrent claims reuse preparing; interrupted/failed attempts stay uncertain and never automatically decode again. Trusted recoverInterrupted advances the attempt revision, fencing later completion. In-flight external writes may leave orphans, which cannot become candidate without the durable fence and matching receipt.

A total operation deadline signals the decoder and bounds opening, streaming, verification and R2 calls; storage transactions are not a hard kernel-time guarantee. Reader/writer cancellation is observed without awaiting an unbounded cancellation promise. Decoder dispose is always attempted, including late timeout returns, and given a bounded one-second wait; unconfirmed cleanup does not authorize retry. No claim that an external compute process stopped is made.

`read` never decodes. Completed read revalidates source, receipt, actual PCM bytes and current eligibility. Candidate means verified retained PCM only: no unit correspondence, quiet-boundary acceptance, playback or publication grant. Factory/source routes are unchanged by this module.
