# Single-unit exact PCM derivative

`buildQuietUnitDerivative({sourceUnitId, pcmBytes, correspondenceInput, correspondenceBytes, correspondenceSha256, measurementBytes, measurementSha256, maxPcmSeconds=1800, maxUnitSeconds=120})` builds one candidate IEEE-float WAV. `correspondenceInput` is the existing `correspondWindowUnits` input including optional explicit diagnostic spans; all canonical/raw/PCM/evidence buffers are copied before asynchronous work. The caller supplies independently reviewed measurement and canonical-source pins. Self-consistent arbitrary replacement inputs do not establish admission authority.

The builder recomputes correspondence from pinned canonical text and raw windows, checks its exact semantic equality with the retained correspondence artifact, and requires the selected unit to be exact-unique with one alternative outside overlap. Unresolved units are refused by this unique-only builder; this is not a universal prohibition on drifted original recordings. No mass preparation API exists.

The full mono16kHz float32 little-endian PCM digest and sample count must match the recognition plan, with finite samples throughout. Original recording-byte hash and decoder execution verification remain the upstream provenance boundary: this builder does not decode or fetch a recording. Source, PCM, decoder, model, config, canonical text, raw window and measurement pins remain in provenance.

Measurement schema `fia-window-signal-boundary-measurements@1` is bound to the exact correspondence, plan, unit text, neighboring raw words, source clock and policy. The builder independently scans actual PCM using10ms windows strictly inside neighboring ASR envelopes, RMS below−45dBFS, contiguous quiet at least60ms, exactly one qualifying run, midpoint cut and centered60ms quiet proof. It compares selected run and sample cut identities with the reviewed measurement. Recorded display dB values are not trusted as acoustic proof. Floating-point source-seconds conversion follows the existing measurement procedure.

The WAV contains exactly PCM[startSample:endSampleExclusive], including its measured quiet margins. Standard RIFF/WAVE uses IEEE-float format tag3, an18-byte fmt chunk, fact sample count and data chunk. Delivery clock starts0 and ends at file EOF; no playback timer trimming, verse/word highlighting, speed transformation or resampling is added. Return value is `{bytes,provenance}` with independent full WAV and sliced PCM hashes.

Limits: full PCM at most1800seconds (115,200,000bytes), one unit at most120seconds, evidence JSON at most4MiB each and canonical manifest at most1MiB. This implementation intentionally materializes bounded PCM supplied by the caller; it is not the streaming source acquisition adapter. Output remains `candidate-not-accepted`, `qualifiedForPlayback:false`, empty accepted ranges. Browser decode equivalence, native whole-file EOF, reviewed eligibility and publication are separate gates.

Run `node --test tests/worker-serving/quiet-unit-derivative.test.mjs`. Tests exercise byte-exact output, identity/cut/neighbor tampering, mutable inputs, nonfinite/noisy PCM and ambiguous quiet runs without media fetching or model calls.
