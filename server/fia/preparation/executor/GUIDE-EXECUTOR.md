# Private guide executor composition

`createGuideExecutor` joins the existing discovery resolver, a trusted free acquisition adapter, a trusted free recognition adapter, the hash-verified presentation unit resolver, exact-word alignment and the existing review-required acceptance adapter. It installs no publish adapter, does not expose pipeline reconciliation, and cannot return accepted playback ranges. Execution permission is separate from playback acceptance.

The constructor takes pinned metadata/registry bytes, optional exact presentation aliases, `readPresentation`, durable `storage`, a discovery `bucket`, `modelRecipe`, `policyRevision`, and `artifacts: {dependencySha256, read, write}`. Optional `admission: {dependencySha256, check}`, `acquisition: {paid:false, dependencySha256, run}` and `recognition: {paid:false, dependencySha256, run}` are captured before any await. Their dependency hashes are trusted explicit implementation/configuration identities; function identity is not inferred. Admission requires synchronous boolean `true` on every request, dispatch, retained verification and returned outcome. A Promise, exception or truthy non-boolean refuses. Missing admission, recognition or acquisition blocks before source work. Paid adapters are rejected at construction.

`resolve(request)` accepts the existing exact discovery consumer request (pack, presentation revision, language, edition, source-unit ID and text hash) and returns the trusted section input. `request(request)` derives that same input and adds only captured model/policy identity. It verifies the retained presentation on every demand, including warm runs. The composition identity binds metadata, registry, aliases, model, policy and all declared capability dependencies; changed dependency pins cannot reuse older pipeline nodes silently. The guide-content script identity and section manifest digest remain distinct.

Artifact reads are hash-verified copies, including Buffer inputs, before existing adapters see them. JSON/evidence is bounded at 4 MiB and acquired original verification at 8 MiB; the injected acquisition adapter may impose a smaller cap (the observed-source adapter retains its 2 MiB policy). Raw recognition must bind actual acquired source hash **and byte length**, the stock local recognition schema, model manifest, runtime/script/configuration, language and finite duration no longer than 600 seconds. Alignment and acceptance retained artifacts are checked against exact unit pins, input identity and parent hashes. Even a hash-valid accepted status is refused: this composition permits only the stock `review-required` disposition and empty accepted ranges.

`stepMs` is bounded to 30 seconds per adapter/read/write wait. A timeout leaves the claimed pipeline node uncertain and does not automatically retry. It does not prove cancellation of the injected capability: a late callback may retain an orphan artifact, but cannot settle that expired attempt. Storage transaction methods and bucket methods are captured; their own runtime durability remains the caller's trusted responsibility. The factory is not a process watchdog or a hosted runtime.

The existing `createObservedSourceAdapter` can be supplied with a validator from `createGuideDiscoveryAdapter` using the same exact metadata bytes/pin. Its immutable acquisition receipt is acquisition evidence, not the stable coordinator's fresh-observation authority. This factory does not replace or mirror that coordinator's freshness head or snapshot CAS.

The required CI wrapper exercises the complete composition with explicit synthetic control fixtures. A separate retained proof uses `FIA_RETAINED_P2` pointing to the existing full 867,865-byte P2 original (SHA `0f3fa9e77215f5050f9e22b7abee329c47e0e9ff71a5f0c4d248926a8f42268d`) and the unchanged retained raw recognition fixture (SHA `4fe40977fbb85f6fea043a9cadeb6f1662a0b3397413256b07096f1b922a1658`). Transport is a local Response through the actual observed-source adapter. The recognition port returns prior candidate bytes; no recognition process, media network request, cropped-source substitution or new acceptance occurs. Without the retained original environment variable, that one proof is explicitly skipped. Tests also cover wrong source/configuration, concurrent ownership, timeouts without replay, warm reuse, revoked admission, immutable capture and corrupt retained evidence.

## Activation boundary

No existing Worker/config/catalog/release file changes in this increment. The current Worker still admits public POSTs through its catalog-only selection, resolves operation IDs through that catalog, and handles alarms through reviewed-original/`prepareAccepted` paths. A production caller must explicitly integrate trusted discovery admission and this factory into the appropriate Durable Object execution path, provide durable artifact ports and a real authorized free recognition capability, then connect only independently accepted complete results to serving. Those callsites, acceptance policy, quality measurements and publication are not installed by this module. Existing accepted P2 playback remains unchanged.

## Next eligible-publication increment

The unchanged retained P2 candidate has two unmatched introductory units (S01-U001/U002), six exact token candidates (U003–U008), and 64 unassigned recognized tokens. These are correspondence findings, not calibrated recognition or timing eligibility. The present acceptance adapter deliberately marks every unit review-required because calibrated recognition, quiet-boundary policy and qualified browser-clock evidence are absent. Thus actual correspondence gaps and the missing policy-qualified acceptance/publication capability are distinct blockers.

The next implementation is a per-unit eligibility adapter that verifies immutable recognition/alignment/signal/browser evidence against an explicitly approved, versioned quality and provenance policy, followed by an immutable publisher behind trusted ports. It must preserve unresolved units without penalizing independently qualified neighbors, bind every acceptance to its exact parent evidence and policy, and publish only coherent eligible results through the existing freshness/snapshot fences. A caller-supplied accepted flag is not that policy. No permanent manual-per-section workaround is proposed; the policy and required quality evidence must be established before automatic publication can be enabled.
