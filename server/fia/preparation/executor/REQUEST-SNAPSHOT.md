# Private request and review composition

`createRequestSnapshots` connects admitted guide-unit acquisition to coherent
snapshot refresh. Trusted observations must match the full logical selection
(pack, language, edition, book, passage, resource), selected source bytes and script.
The recognition configuration root hashes canonical
`{schema:'fia-recognition-recipe@1', ...modelRecipe}`: model ID, model revision and
settings identity all participate. Trusted policy, storage and eligibility ports
are captured before asynchronous initialization.

The builder runs actual request acquisition but always returns blocked. There is
no production accepted-output builder: recognition capability, calibrated semantic
and quiet-boundary acceptance, delivery-clock evidence, rights admission and
presentation assembly remain missing. A previously accepted eligible snapshot can
remain served in full; unavailable or revoked snapshots are not served. The return
separates snapshot state from this attempt's preparation result (null when an
existing refresh was reused). No public route, ASR activation or generated fallback
is added. Only admitted original recordings enter this path.

`createComparisonEvidenceAdapter` takes a fixed, trusted structural-context array
at asynchronous construction. Contexts and versification are not discovered or
canonically authorized here. It captures that array and hashes it with the actual
spoken policy, grammar, book and number tables. It retains a derived word view with
raw recognition hash and reversible segment/word indexes. Original recognition
bytes, confidence, wording and timestamps remain unchanged. Per-comparison pins
include context, versification and normalization identity. Comparison only adds
review diagnostics: it does not modify alignment mappings or grant acceptance.

The optional comparison adapter passes its dependency hash through the acceptance
adapter. Pipeline operation identity includes installed adapter dependencies;
node identity includes dependencies through that node, and reconciliation checks
the same pins. A changed comparison context invalidates acceptance and descendants,
including when output bytes happen to be identical; predecessor acquisition,
recognition and exact alignment remain reusable because comparison does not alter
those operations. An absent dependency retains the previous identity format.

Validation includes actual local SQLite/R2 acquisition and restart with zero
publisher calls, prior complete snapshot preservation and revocation. The accepted
prior graph and routing metadata are explicit fixtures, not acoustic acceptance or
new passage coverage. Integrated comparison tests exercise actual alignment,
comparison, acceptance and pipeline caching with synthetic recognition. No hosted
recognition, new publisher fetch or deployment occurs. Source freshness PR167 is
not part of this candidate. Release closure and production acceptance remain open.
