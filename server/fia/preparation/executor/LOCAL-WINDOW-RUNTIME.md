# Local window execution

`createLocalWindowAdapter` is an offline development/reference capability, not a hosted service. It uses the existing PyAV and faster-whisper CPU/int8 interfaces and requires an already installed runtime and hash-pinned local model. It downloads nothing and acquires no URL. Tiny English models refuse Spanish.

`decode({sourcePath,sourceSha256,sourceBytes,signal})` verifies at most 8 MiB of source bytes, decodes a single audio stream to mono 16 kHz float32 little-endian PCM on disk, and returns the measured receipt plus a recognition capability. The decoder flushes its resampler. `maxSamples` bounds disk output (default 1,800 seconds, approximately 115 MB); a caller may explicitly choose up to the planner's 24-hour ceiling. This ceiling is not measured throughput or a memory guarantee. Decode and recognition subprocesses have a 120-second watchdog, with a configurable outer timeout up to 125 seconds. Post-decode verification is abortable and shares the outer decode deadline.

Plan with the returned measured source/PCM/decoder pins and the adapter's model/config pins. The recognition capability accepts `{planIdentity,window,signal}` and returns raw JSON bytes. It revalidates the deterministic plan/window, reads at most 600 seconds of PCM into memory for the model, and hashes the complete PCM in the same read sequence used to extract that window. Each request verifies the model manifest and runtime. Local executable/model directories require trusted immutable custody during execution; this is not an OS sandbox.

Raw artifacts retain original model segments, word seconds/probabilities, settings, runtime identity, exact window identity, and the explicit `seconds-floor-start-ceil-end@1` conversion. Invalid, reversed, out-of-window, or zero-duration word clocks refuse the window rather than inventing positive timing. Both overlapping windows' words remain in projection; reconciliation is unresolved and no playback acceptance is created.

Pass `decoded.recognition` to `createWindowRecognitionExecutor`. Its transactional storage and immutable artifact ports are caller-owned. Completed windows rehash retained raw evidence and never invoke recognition again. `recoverInterrupted` is a trusted single-owner startup operation; it fences persisted preparing attempts as uncertain. Ordinary concurrent requests do not infer that a live owner crashed. Uncertain windows have no automatic reset/retry path. The window-count budget is per pinned plan/dependency, not an account-wide quota or a scheduler.

Cancellation sends SIGKILL to the direct local child and waits for its close event before reporting the process stopped. If closure cannot be confirmed within five seconds, the adapter reports termination uncertainty and retains its scratch paths. This does not prove termination of arbitrary descendants or enforce an OS memory limit. The executor fences late completions even when a capability ignores cancellation; already issued artifact writes may leave unused immutable bytes. Call the decoded result's `dispose()` only after recognition settles. No concurrent disposal guarantee is provided.

Factory/Worker wiring, source admission, hosted execution, retry authority, long-file capacity qualification, overlap reconciliation, alignment, and publication remain separate caller responsibilities. No existing factory or guide-dispatch behavior is changed by these files.

## Verified streaming input

`decodeStream({source,openSource,maxBytes=2097152,totalMs=120000,signal})` consumes the typed retained-source port. `source` contains exactly the SHA-256, `originals/sha256/<sha>.mp3` reference, and positive byte count. An explicit trusted `maxBytes` may be at most 16 MiB; this does not change dispatch admission or the legacy `decode` method's 8 MiB limit. The consumer copies at most 64 KiB per chunk into a private temporary file while checking SHA/count. It waits for the producer's `verified` promise, including final admission/lease checks, before invoking Python. Producer failure never falls back to whole-source bytes.

The new Python mode incrementally rehashes the completed private spool and passes that same seekable file descriptor to PyAV, without `read_bytes` or `BytesIO` materialization. This relies on immutable private-file custody during decoding; it does not protect against a same-user process modifying file contents concurrently. Source spools are deleted after confirmed decode completion or failure; termination uncertainty retains scratch paths rather than claiming cleanup of a live process.

There are two bounded phases: `totalMs` covers producer opening, source reads, and verification; the existing `processMs`/Python watchdog governs decoding and PCM verification separately. These are not one end-to-end deadline, and filesystem completion is not a hard OS I/O guarantee. The source consumer invokes no model. Its measured P2 proof verifies identical PCM hash/sample count to the retained legacy decode; synthetic large-source spool tests do not establish long-recording decode/recognition capacity.
