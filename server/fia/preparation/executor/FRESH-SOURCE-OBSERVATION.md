# Explicit admitted fresh-byte observation

This private module implements the original-byte observation portion of cookbook PR174, `SOURCE-FRESHNESS-RECIPE.md` SHA `2b3f10bd66638187e8921bd3e5a9f41a71696d9f05888bd0c2843ec0c419e436`. Base: `1401c2aa09bca0a6d6405fb4ee77a3e51b5ba944`. It adds no public route, production admission adapter, source catalog, scheduler, paid operation, hosted binding, deployment, playback acceptance or pipeline invocation. Existing acquisition, coherent-snapshot coordinator, 2 MiB original store, serving and release code remain unchanged.

`createFreshSourceObservations({storage,bucket,source,policy,admissions,eligibility,fetchSource?,makeStream?,now?})` captures trusted resolved source/policy/admission values and callback references. Source has logicalId, exact literal HTTPS URL (no credentials, query or fragment), sourceVersionKind (`discovery-snapshot` or `publisher-version`), sourceVersion and nullable publisherVersion. A snapshot version remains a snapshot version even when audio bytes change; actual observed SHA is a separate receipt field. Publisher-version claims must match the explicitly supplied trusted publisherVersion. The factory accepts no `observed-content` version label that could mistakenly identify newly changed bytes with a previous content hash.

Policy supplies revision and explicit maxBytes/totalMs/progressMs, bounded by 8 MiB, 120 seconds and 15 seconds. Admissions are at most 32 trusted tickets, each with checkId, unique monotonic sequence, expectedPreviousObservationSha256 and previousSourceSha256. The first expected head and previous source must both be null; no implicit baseline exists. Callers of `observe(checkId,{signal?})` cannot invent another check ID, URL, key or revision. This is an internal capability contract: an independently trusted admission component must issue tickets and apply real authorization/budget policy. The module does not turn a request body into admission authority.

A durable ticket key binds logicalId+checkId independently of policy. Redeclaring the same ticket with different source, policy or admission refuses. Durable logicalId+sequence binding also refuses aliases across factory instances. Identical admitted calls share the attempt; later independently admitted checks always perform their own full GET, including when the original is already retained. No warm object can substitute for that fresh response. Expected prior head/source and sequence are checked at claim; retained prior head receipt/content is verified before the next GET. Each source context, policy and ticket is bound into the operation digest.

The required synchronous `eligibility` callback receives phase, exact source context, admission and observedContent (null before dispatch, then actual SHA/bytes at head promotion/read). Strict true is required; promises, rejection and exceptions fail closed. It must consult current trusted access/rights/known-bad/admission state. Eligibility is checked immediately before dispatch, at final head transaction and after verified head read. A revoked or newly known-bad observation may remain historical evidence but cannot advance the head. Metadata status and explicit reconciliation are inspection tools, not audio-serving authorization.

This slice requires a valid response Content-Length from 1 through the admitted cap. Missing, malformed, zero or oversized lengths are explicitly unsupported/refused, not treated as unchanged or observed. R2's known-length stream requirement is satisfied by FixedLengthStream; unqualified unknown-length buffering/multipart is not implemented. Status must be 200, MIME audio/mpeg, and redirect handling is manual. Actual bytes independently determine the hash and must match the declared length. A false header, truncated body, cap+1, stall, total deadline, cancellation or oversize input chunk cannot yield a completed observation.

The source streams into an attempt quarantine object using at most a 1 MiB accepted input chunk and 64 KiB write slices/backpressure. No whole-source array is created. Quarantine is rehashed, the content-addressed original is published create-only, and the retained race winner is streamed and verified. Existing corrupt bytes are never overwritten. Runtime/library buffering is not measured by this application chunk bound. Every external fetch/put is invoked outside the durable transaction callback after the durable ownership check, so transaction callback replay does not duplicate external work. An operation submitted before a timeout can still leave an orphan; final attempt/head fences prevent it from becoming a completed latest observation. No unbounded cancel wait or automatic quarantine cleanup is used.

Unchanged bytes reuse the original and append a new check receipt. Changed bytes create a distinct immutable original plus an append-only kind-preserving source-context-to-content mapping. All observation receipts record the actual fresh response, content size/hash, admitted operation/attempt, prior head/source and observation time. `changed` compares actual hashes; it does not trigger recognition or a bulk rebuild. A separately composed downstream coordinator decides which actual dependent identities need replacement.

Receipt/reference publication precedes the atomic attempt/head transaction. A newer admitted check can complete before an older transfer; the older check may complete a historical receipt but reports `promoted:false` with `fresh-stale-head`, never replacing the newer head. `promoted` is historical at that operation's completion, not a claim that its receipt is still the current head. `fresh-ineligible` distinguishes a completed but excluded observation. This head is independent from accepted playback/presentation heads.

`read()` verifies the full canonical head receipt, immutable original and reference on each call, with zero publisher GET, and returns observed evidence with `acceptedPlayback:false`. It does not claim freshness at read time. `status(checkId)` returns explicitly labelled durable-operation metadata only. Interrupted/unknown attempts stay uncertain and never automatically retry. `reconcile(checkId,{attemptId,revision})` verifies a completed receipt, or verifies a retained historical receipt after an interrupted final commit without promoting it. If no receipt survived, uncertainty remains; no new GET, requeue, recovery promotion, serving permission or writer cancellation proof is inferred.

Tests: `node --test tests/preparation-executor/fresh-source-observation*.test.mjs`, with `FIA_WORKER_DEPENDENCIES` selecting the existing installed Worker dependency package. They use actual local SQLite/R2 with fake publisher bytes, plus a deliberately replayed transaction-callback fixture. Coverage includes fresh-versus-warm behavior, changed/unchanged bytes, admission/sequence/source/policy conflicts, current eligibility, exact cap and excess, missing/false length, MIME/redirect/stall/abort, out-of-order completion, restart, corrupted retained objects and interrupted receipt/head commit reconciliation. No real publisher is contacted. Actual provider ACLs, authorization and spend budgets, unknown-length sources, decode/ASR, accepted semantic/timing evidence, client adoption and hosted execution remain unimplemented by this increment.
