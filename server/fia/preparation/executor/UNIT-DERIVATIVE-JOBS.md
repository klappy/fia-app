# Demand-keyed candidate unit derivative jobs

`createUnitDerivativeJobs({storage,artifacts,resolveInputs,eligibility,dependencySha256,stepMs=30000,maxPcmSeconds=1800,maxUnitSeconds=120})` uses existing transaction and immutable artifact ports. There is no Worker route, hosted activation or separate infrastructure. It exposes `request(demand)`, read-only `read(demand)` and trusted recovery `recoverInterrupted(demand)`.

A demand is exactly `{sourceUnitId,sourceTextSha256,pins}`; pins are sourceSha256,pcmSha256,canonicalSha256,correspondenceSha256,measurementSha256,planSha256,windowSha256,rawSha256. The canonical manifest includes consumer identity. The durable key includes all these pins, builder policy `quiet-exact-pcm-float-wav@1`, limits and trusted dependencySha256. Changing actual dependency pins separates the demand; caller aliases cannot replay an uncertain identical demand.

`resolveInputs(demand,{signal})` returns the actual quiet-unit builder inputs. It must only resolve admitted retained data, with current source/canonical/measurement provenance. `eligibility(demand,phase)` must synchronously return exactly true; promises, truthy values and throws refuse. Its references and artifact/storage methods are captured at factory creation. Artifacts expose `write(bytes,{kind:'wav'|'receipt',signal})` and `read({sha256,reference},{signal})`; writes must be immutable/create-only. The node independently hashes bytes and verifies readback.

A transaction claims before input resolution or generation. Concurrent identical requests observe preparing. No timer or new incarnation implies an interrupted task stopped; only the internal recovery operation marks preparing uncertain and advances its revision. It does not cancel outside work or permit retry. Every later artifact/adoption stage checks exact attempt/revision and current admission. A late orphan immutable artifact may exist after a port timeout, but cannot complete a fenced/uncertain job. Per-port waits are bounded; storage transaction completion and synchronous CPU work are not a hard wall-clock execution guarantee.

Cold execution invokes the actual exact-PCM builder for only the requested unit. WAV and provenance/projection receipt are separately content-addressed. The receipt preserves every correspondence unit's lexical status and adds a candidate descriptor only to the demanded exact-unique unit. It does not mark other units failed or accepted. Warm read/request rehashes receipt and WAV, validates identity/provenance/header/sliced-PCM digest and current admission, with no resolver or generator invocation. Missing/corrupt artifacts return unavailable; they are never silently regenerated.

Returned state `candidate` is explicitly not playable admission. All outputs retain qualifiedForPlayback:false and empty accepted ranges. Measurements, browser/native qualification, publication and client exposure remain separate. Current factory lacks retained PCM/measurement demand ports; installing this node alone does not activate a production route. Upstream rights/provenance and dependency pins remain trusted injection boundaries, not self-authorizing fields from a public request.

Run `node --test tests/worker-serving/unit-derivative-jobs.test.mjs`. Root-owned actual SQLite/R2 integration supplements the focused in-memory transaction tests; no network/model invocation is required.
