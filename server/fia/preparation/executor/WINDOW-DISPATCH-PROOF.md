# Window recognition through the request dispatcher

This composition starts from reviewed streamed factory `3f79b8c`, includes the reviewed sample-window planner and local runtime, and preserves the `ddface38` test-only recognizer timeout correction. Both cold-start recovery fixes remain in the base. The only dispatcher production change preserves an explicitly supported recognition result-schema marker; absent capabilities remain inactive.

The opt-in factory consumes `fia-window-guide-recognition@1`. It verifies each retained raw artifact, deterministic plan, model/config/source pins, and recomputed projection on both cold and warm paths. It emits distinct unresolved correspondence and review-required evidence containing the current canonical unit identities. Overlap is retained, never concatenated into a claimed continuous transcript or exact alignment. Accepted playback ranges remain empty.

The actual local Worker/SQLite/R2 test dispatches retained P2 through admitted streamed acquisition, factory, measured PyAV decode, and three 30-second windows with two-second overlap using the already-installed offline tiny English model. It then restarts storage and forces a factory warm traversal: source, decode, model, and external-network call counts remain zero. Corrupting a nested raw artifact refuses reuse without rerunning recognition. Removing typed stream provenance refuses source reuse without acquisition or fallback to a legacy receipt. A model call held before invocation is interrupted, fenced, and remains uncertain after restart without replay. A second audited request, P3, runs two actual windows and retains its separate source and canonical identity.

The local model is reached through an in-process Miniflare service binding for this test, not a hosted HTTP deployment. Source bytes are supplied from retained local MP3s. No publisher request, paid ASR, download, public activation, playback approval, or bulk preparation is performed. The source-byte limits remain unchanged: dispatcher admission 2 MiB, dispatcher artifact reader 4 MiB, stream adapter 8 MiB. The JSON artifact cap is separately 4 MiB. A typed streaming-source interface and larger explicit source budget are a separate review; this test still materializes its small retained source bytes.
