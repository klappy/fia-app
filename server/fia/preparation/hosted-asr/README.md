# Private hosted ASR pilot control prototype

Recipe: cookbook PR180, merge `7f863cca354514bf365f7422d992e16f23f08b19`.

`createHostedDispatch` accepts trusted constructor-only semantic identity, activation, fixed ledger A or B, durable transactional storage, an infrastructure executor, retained artifact reader and strict domain result validator. There is no HTTP interface. Both ledgers share one node identity, one two-start budget and singleton exclusion. A failed or ambiguous dispatch consumes its start and remains uncertain. Warm results are rehashed and domain-validated. Completion requires verified executor stop; a persisted shortened deadline and alarm bound the stop tail to 30 seconds. Failed stop remains uncertain and blocks the other ledger. A trusted explicit reconciliation can finish the same fenced attempt before its original deadline; it cannot allocate another attempt.

The executor must establish actual enforced resource limits before setting `limitsEnforced`. This boolean is a trusted integration capability, **not evidence that this module enforces memory or scratch limits**. PR156 CI run37383812068 built and loaded the CLI image under verified Docker resource flags. This is not Cloudflare enforcement. The private integration below is implemented but not deployed. The deployment owner must bind an immutable enforcement receipt and the pinned pilot identity, and implement ready/recognition/idle subdeadlines before activation. The durable alarm must call `watchdog` for the appropriate fixed ledger after restart.

`runBoundedProcess` is a Node development process-group supervisor with an absolute wall-clock deadline, output bound and TERM→KILL escalation. It does not enforce RSS or filesystem quotas and must not by itself authorize hosted dispatch. Stop verification concerns OS process-group absence, not infrastructure billing termination.

Direct tests: `node --test tests/preparation-hosted-asr/dispatch.test.mjs tests/preparation-hosted-asr/watchdog.test.mjs`.

Tests include serialized in-memory storage, actual local Miniflare SQLite DO persistence across full runtime restart, and real local child processes. They do not prove hosted operation. Separate actual local Miniflare R2 tests prove local create-only publication and restart behavior. artifact.mjs provides bounded raw segment/word validation and create-only R2 body/isolated-ledger receipt publication with readback verification; mock-R2 tests exercise conflicts and corruption. The private executor must use these functions as its validator/publication adapter. No provider call or existing alignment compatibility is claimed. This is a bounded control prototype, not a deployable hosted ASR service.

Persisted records and both ledger states are validated before reuse or exclusion. A stop call is bounded to 30 seconds, but timeout does not cancel the native operation. An unresolved exclusive stop lease disables automatic stop retry and remains uncertain for explicit operator intervention. This does not authorize compute retry or imply that billing stopped. Failed dispatch triggers immediate bounded shutdown. The image-local watchdog and verified infrastructure stop remain required independent protections.


## Private integration follow-on

`cloudflare-worker.mjs` exports the dedicated DEV Durable Object. Both Worker and DO HTTP fetch return404. Private RPC selects fixed ledgers A/B; the class checks its actual object ID against the fixed namespace singleton before work. `cloudflare.mjs` composes durable dispatch with native default-policy Container startup, readiness, source read from FIA_ORIGINALS, bounded HTTP recognition, strict raw validation, immutable R2 publication, verified whole-container stop and restart-safe alarm cleanup. Persisted activation supports cleanup after deployment configuration is disabled. Corrupt attempt/budget state cannot suppress the emergency stop attempt.

`pipeline-adapter.mjs` binds normal pipeline recognition to ledger A only. Its recipe hash includes exact source/model/runtime/recognizer/configuration plus image, enforcement and review receipt pins. The existing alignment adapter accepts the hosted raw schema only through an explicit trusted validator returning true; raw candidate bytes remain unchanged. No confidence or playback acceptance is inferred. The generic pipeline warm-restart test uses actual retained pilot source bytes with synthetic recognition evidence; it is not an ASR accuracy test.

`activation.mjs` validates trusted deployment configuration, not public input. Receipt hashes bind reviewed evidence; syntax and a claimed boolean do not prove enforcement. `deploy/hosted-asr/activation-config.mjs` generates a review-only dedicated executor config plus DEV caller binding addition and rollback instructions. No checked-in enabled activation is supplied. `activation-plan.json` records distribution gaps, cost assumptions and remaining product scope.

The integration image applies a hard4GiB virtual-address-space limit per process and an inherited kernel filesystem-write denial before native model imports. Zero filesystem writes is stricter than the256MiB scratch ceiling. Readiness fails if required Linux kernel guards are unsupported; Cloudflare kernel compatibility remains unknown. The default scheduling policy is required because the newer durable_object policy retains root capabilities regardless of numeric UID. A dedicated CI run must prove the actual entrypoint, guarded model load and one bounded HTTP recognition. It does not authorize registry upload or deployment and cannot prove hosted enforcement.

Stop execution now has a durable exclusive lease, claimed before alarm or native API awaits. Concurrent shutdown/reconciliation cannot issue a second stop or complete the first. Only a positively verified stop resolves the lease. False, thrown and timed-out outcomes retain a pending lease and block completion, reconciliation and the other ledger; later shutdown success cannot certify that an older timed-out destroy can no longer fire. Automatic shutdown retry is disabled for an unresolved lease; the previous three-attempt retry behavior is no longer used. Stronger operator recovery evidence remains an explicit gap; never erase ledgers or budgets to recover. Old persisted stop records lacking lease evidence fail closed.

Emergency cleanup also claims a permanent singleton quarantine before native destruction. Admission, completion, and the last checks before start/request/publication all consult this durable marker. A verified emergency stop does not clear it: other old native operations may remain unresolved. Private status reports the sanitized quarantine state. Repeated alarms do not launch another emergency destroy; recovery requires separately reviewed operator evidence and has no automatic reset path. SQLite tests cover a gated emergency destroy, an already-waiting source read, and persistence across runtime restart. Containers and recognition remain simulated in these local tests.
