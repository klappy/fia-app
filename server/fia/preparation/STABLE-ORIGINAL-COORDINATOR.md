# Stable reviewed-original coordinator

The existing `FIA_PREPARATION_JOBS` binding owns both unchanged public operation IDs and an internal stable selection namespace. The internal object verifies its actual Durable Object ID. Selection comes from the trusted catalog, including pack/book/passage/language/edition/resource/quality; presentation and source revisions do not enter that key. There is no public internal route, new binding, or migration.

A unique eligible reviewed-original admission is current. Multiple admissions require exactly one trusted `coordinatorCurrent: true`; the flag is routing authority, excluded from immutable admission hashing. Historical admissions can read independently eligible retained snapshots, but cannot reserve a refresh. Only explicit preparation POST schedules demand. One durable ticket per immutable admission performs a genuine fresh GET even if identical source bytes already exist. Unknown length is refused; the current policy caps bodies at 2 MiB, total acquisition at 30 seconds and stream progress at 15 seconds. Failed/interrupted tickets are consumed and do not automatically retry. This implementation does not perform ASR or accept newly changed source bytes.

Fresh observation storage and reviewed snapshot storage are colocated. A distinct desired sequence/attempt captures the expected prior served snapshot. Promotion checks that exact attempt, expiry, current admission, prior snapshot, and complete current local freshness token in the same SQLite transaction. Freshness and desired sequences are separate domains. Every read verifies retained original/reference and the complete reviewed evidence joins, then rechecks both heads and eligibility transactionally. A changed desired source can coexist with a separately verified old complete snapshot. The public adapter refuses a retained result whose presentation does not match the requested client revision.

For rollback, a successful new result additionally rebuilds the previous runtime's per-operation verified source receipt and reviewed snapshot from retained immutable bytes/evidence. That compatibility cache is not freshness authority. Legacy jobs and alarms remain unchanged until an explicit reviewed-original POST upgrades them. The public audio route can retrieve the immutable reviewed original through the stable coordinator even when an older same-SHA admission has no per-operation job.

Validation uses actual local Worker HTTP, SQLite and R2 with synthetic publisher/evidence fixtures. It includes two revisions, failed replacement, late completion, current-admission revocation, wrong native object ID, offline restart, same-SHA audio GET/HEAD/range and frozen previous-runtime rollback. Fixtures demonstrate storage/control flow, not new timing review, production freshness, hosted execution, or playback acceptance. No publisher requests or deployment are part of this change. Explicit ticket recovery, arbitrary refresh scheduling, and unknown-length acquisition remain outside this slice.

## Existing-original request sidecar projection

The stable coordinator now composes a fully verified existing reviewed-original outcome through `executor/request-sidecars.mjs` using `stable-original-sidecar.mjs`. This borrows the reviewed store and existing request-sidecar primitive rather than adding a preparation engine (borrow-evaluation-before-implementation). The pure capability is `reviewed-original-mapping`; it introduces no accepted mappings or inference policy. The result and served/desired selection response shape remain unchanged.

Identity binds both desired and served selection, the complete served snapshot digest, admission, original, script, units, original-store policy, prepared result, recording ledger, timing, and acceptance digests. The adapter recipe is `fia-stable-original-sidecar@1`. Evidence points to the existing four immutable reviewed-original documents and unchanged original MP3. Validation re-reads the original store, including actual source bytes and all evidence joins. Eligibility rechecks desired and served admissions plus the captured control, freshness and served snapshot heads in SQLite. A changed head cannot expose a mixed result. Failed replacement continues to project only the complete eligible old snapshot, and the public adapter still refuses mismatched requested revisions.

No upstream work starts from this adapter: the shared port returns the verified outcome already obtained from the existing coordinator. Only an already explicitly requested, observed stable snapshot can reach this projection. A missing sidecar can be completed during status recovery after that demand; warm reads revalidate and reuse it. Corrupt retained sidecars are refused and never overwritten or hidden by reacquisition. Browsing, automatic retries, ASR, generation and new source admissions are unchanged.

Persistence uses the existing SQLite `request-sidecar:<identity hash>` immutable pointer and `request-sidecar-subscriber:<hash>` records, with R2 `preparation/executor/<content hash>.json`. There is no new binding or migration. A unique internal subscriber per missing-projection attempt avoids concurrent readers detaching each other's projection; after publication, warm reads create no subscribers. These are internal projection attempts, not playback subscriptions; client cancellation remains owned by the existing client and no automatic playback is introduced. A crash before pointer publication retains content-addressed bytes; the next status read repeats only deterministic projection and verified publication. Originals, evidence, sidecars and attempt records are retained without new TTL/deletion. Rolling back ignores these additive records and retains the established prior-runtime compatibility path.

The coordinator suite now has 11 passing local Worker/SQLite/R2 tests, including sidecar identity/evidence inspection, unchanged bytes and zero upstream work across warm/offline restart, corruption refusal, complete old-snapshot retention, revocation and stale-promotion races. Its esbuild harness now externalizes `node:*` so the integrated canonical-ledger `node:zlib` import is supported. These synthetic fixtures prove persistence/control flow, not new semantic acceptance or live deployment.
