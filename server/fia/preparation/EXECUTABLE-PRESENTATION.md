# Server executable presentation domain

Contract authority: independently reviewed cookbook `7fa17af806c139cfc353cace39fa6d50ed9e061b`, SOURCE-TO-APP-CONTRACT.md and corrective projection@2 schema. This domain composes existing published source content, validated persisted interpretation, generic decision jobs, and request sidecars. Publication/HTTP/MCP and client execution belong to their existing adapters. A schema-valid decision or successful job alone is not semantic truth.

## Portable compiler boundary

`compiler/presentation/source-action-projector.mjs` exports `canonicalSourceOrder`, `validateSourceActionDecision`, `validateBoundArtifacts`, `validateExecutablePresentation`, `projectExecutablePresentation` and the recipe `fia-server-source-action-projector@1`. Existing `compilePresentation` remains synchronous and unchanged. Its new optional `compileExecutablePresentation(input,{sourceActions,...options})` hook feeds the same compiled pack into this portable projector. The Worker imports only the portable domain; it never imports Node filesystem compiler code or reimplements semantics in UI.

The checked-in input/result schemas preserve the previously pinned structural drafts. The projection schema is the exact corrective@2 file at the reviewed contract. The new `executable-presentation.schema.json` registers closed execution fields on EVERY activity while preserving existing presentation display/provenance fields. Domain validation additionally enforces source, context, candidate and asset membership, compound role consistency, source order, activity/reference bindings and narration ownership; schema validity alone never grants semantic acceptance.

Canonical units are exactly `{sectionId,sectionOrdinal,sourceUnitId,unitOrdinal,sourceTextSha256,text}`. All actual text hashes are checked; units must be unique and ordered. The canonical order digest hashes canonical JSON of those units with `text` omitted. This includes original source units omitted from the active presentation as examples, so activity bindings retain their actual canonical ordinal. Decision context is at most four contiguous adjacent source units from this verified sequence.

`projectExecutablePresentation` takes `{basePresentation,baseRevision,sourceRevision,language,canonicalUnits,canonicalOrderSha256,decisions:[{input,result}],transitionEvidence?,narrationBindings?,boundArtifacts?,recipeRevision?}`. The caller supplies a verified coherent base and trusted source revision; production resolver separately verifies original immutable bytes against publication authority. Repeated calls with identical base/evidence/recipe return identical output. An already projected presentation cannot become a new base and append resources again.

Only independently confirmed requested-medium relations add focal actions. Existing supplements are not promoted to requested steps. Every confirmed ID survives; ambiguous alternatives never pick one. Simultaneous confirmed views follow existing verified base asset order, never candidate/provider order. The primary keeps ID/text/prompt/source narration and becomes manual discussion with first focal asset. Additional resources appear immediately afterward using `${primaryId}-resource-${assetId}`; they retain readable source provenance but have empty narration, null legacy audio fields and explicit narration:none. ID collision, orphaned/cross-anchor owners, incompatible legacy/explicit fields and forged references fail before publication. Global asset graphs are unchanged. Multiple explicit requested views are distinct from ambiguous interchangeable candidates.

Transition uncertainty is separate from narration eligibility. Trusted `transitionEvidence` records are exactly `{activityId,sourceUnitId,sourceTextSha256,status:'resolved'|'unknown',action:'manual-continue'|'advance-after-narration',reason,evidenceSha256,policySha256}`. They bind exact source identity. Existing reviewed descriptive-list auto behavior and Scripture/discussion manual handoffs remain supported. Resolved substantive/manual cue roles force manual. Without applicable transition evidence, retain a manual hold with `transition-unknown` provenance; all-false roles and a legacy guide kind do not prove auto. Narration remains independently bound/preparable when supported.

## Bound narration execution

Full `presentation.execution` is exactly `{schema:'fia-executable-presentation@1',sourceRevision,decisionEvidenceSha256,recipeRevision}`. Every `activity.execution` is exactly `{narration,focalAssetId,completion}`. Completion contains only action manual-continue or advance-after-narration. Narration contains exactly one action:

- `{action:'none'}` for secondary source narration or an explicitly supplied no-narration capability.
- `{action:'prepare-original',demand:{id,sha256}}`.
- `{action:'play-bound-audio',artifact:{id,sha256}}`.
- `{action:'blocked',status:'unsupported'|'unavailable'|'invalid',reason}`.

Bound artifacts are `{id,bytes:Uint8Array,sha256}`. Their bytes are verified JSON with at most65,536bytes. Demand JSON: `{schema:'fia-bound-narration-demand@1',id,identity:{packId,presentationRevision,language,edition,quality:'original',activityId,sourceUnitId,sourceTextSha256}}`. Approved audio JSON: `{schema:'fia-bound-narration-audio@1',id,delivery:{url,sha256,bytes,mime},playbackRange:null|{startSeconds,endSeconds}}`. Source demand identity must match its owning activity. Approved audio requires trusted server acceptance and exact existing range/delivery proof from composition; a well-formed URL is not authority. Domain validates closed shape, byte identity and references. Production root supplies current authority; neither user JSON nor provider output can supply bound grants. Missing bindings are blocked, not dropped. Source semantic decisions cannot grant audio.

## Durable decision service

`createExecutablePresentationService({storage,artifacts,resolve,eligible,interpret?,narrationFor?,policySha256,recipeRevision?,decisionJobs?})` returns `request(args,{subscriberId?})` and `read({jobId})`. `args` exactly `{packId,baseRevision,sourceRevision,capability:'executable-presentation'}`. `eligible(args,phase)` is async current server authority. `resolve(args)` is the trusted immutable publication/source resolver, called only by explicit demand.

Resolved context: `{basePresentation,baseRevision,sourceRevision,language,guideContentSha256?,canonicalUnits,canonicalOrderSha256,decisions:[{input,explicitResult?}],transitionEvidence:[],boundArtifacts:[],narrationBindings?}`. Optional `narrationFor(activity,context)` supplies trusted bound actions during demand only. Interpretation port is `null` or `{dependencySha256,run(input,{signal})}`. Its dependency identifies actual provider/configuration/policy composition. Explicit results must come from applicable trusted evidence, not per-unit production admission tables. Input/decision joins and matching `policySha256` are verified before retention and on warm reads.

Each bounded decision uses `executor/decision-jobs.mjs` with a single fenced attempt,10s stage budget,65,536byte decision ceiling, immutable readback and no automatic retry. It does not masquerade as an audio transcription stage. Missing provider produces a persisted typed unknown/unsupported result with provenance mode:none and provider-unavailable reasons, retaining instructions and partial structure. Synthetic test providers are not installed in production and are not model quality evidence.

Ready service output is `{status:'ready',jobId,presentation,boundArtifacts,provenance}`. Ready describes a validated executable artifact, NOT resolved semantics for every instruction: inspect provenance.unresolved and transitions. Root publication overlay persists those exact bytes and bound artifacts, then adopts its eligible pointer. Other statuses are preparing/blocked/unavailable with reason. The service never publishes a catalog pointer. Shared decision completion is not automatic playback.

Read loads only immutable context and already-retained decisions/sidecar, revalidates current eligibility and all joins, and recomputes the pure projection for comparison. It does not resolve new source inputs, invoke provider, acquire media or create a missing sidecar. If a crash completed decisions before sidecar publication, status remains preparing until an explicit demand recovers deterministic projection. Context is capped at1MiB; unsupported size fails rather than dropping source/candidates. Artifact port must supply bounded R2 I/O; the generic decision job independently bounds its I/O. Current root composition provides that port.

## Persistence and custody

Existing SQLite owns additive `executable-presentation:job:<jobId>` immutable request/context descriptor, generic decision-job attempt records and request-sidecar pointers/subscribers. Existing R2 artifact port owns immutable context, decision evidence and sidecar JSON. Context carries bytes of bound narration JSON, serialized deterministically for retention. Policy/provider/recipe/context changes yield distinct job identities. Reusing an old job under changed service policy is refused. No new binding, migration, TTL/deletion or automatic scheduler.

Consumer-side cancellation must discard stale presentation adoption; existing generic sidecar subscriber fence prevents detached publication where wired. This service exposes no new public cancellation tool or playback action. Shared provider jobs are not canceled by a consumer. Root owns exact MCP4-operation registration and current catalog/artifact read authority, including old pinned hash revocation. No route, deployment or corpus-wide readiness is established by this module alone.

## Tests and limits

`tests/preparation/executable-presentation.test.mjs` exercises generic EN/ES/arbitrary IDs, candidate-order invariance, exact base resource display order, multiple confirmed same-slot views versus ambiguity, manual adjacency, source narration once, preserved eligible narration under unknown transition, schema/evidence/anchor/conflict refusal, warm service recreation with zero additional provider/resolve calls, unavailable provider outcomes and corrupt context refusal. `tests/compiler/presentation.test.mjs` preserves existing compiler behavior over all136 source packs. The exported fixture is synthetic development evidence for actual MCP/engine/browser integration, never new semantic acceptance.

Remaining integration requirements: actual MCP read_pack/read_artifact byte equivalence, production canonical resolver + current narration/semantic authorities, client consumption and non-first full-script journeys, and DEV→staging→production release. Missing semantic provider stays explicit. No paid/model activation or media/video change is authorized or performed by this domain increment.
