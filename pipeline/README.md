# @fia-app/pipeline — FIA Alpha content pipeline (lane L1)

Aquifer FIA repositories → catalog manifest (C-03) for all 17 languages → per-pericope content packs (C-02/C-04/C-05/C-08) → rights records (C-13). Runs server-side (Node ≥ 20, ESM, no framework); never on the device. Nothing is generated by AI in this lane: AI-backfill slots are laid out and marked `ai: true` (M11 default: generated on demand server-side later); Scripture is never AI-backfilled; nothing is invented (epic RULING).

## Run

```sh
cd pipeline && npm install
npm run pin        # re-resolve every repo's HEAD via `git ls-remote` and rewrite sources.json (C-01 pins)
npm run catalog    # data/catalog/manifest.json (C-03) + data/catalog/<lang>.json (detail) + data/catalog/COVERAGE.md
npm run rights     # data/rights/records.json (C-13) + data/rights/NOTICE.md (verbatim licence fields)
npm run pack -- spa MRK-1-1-13      # data/packs/spa.MRK-1-1-13/{manifest,guide,guide-units,scripture,resources,narration,narration-plan}.json
npm run proofs     # the five proof packs
npm test           # ajv validation of every output against pipeline/contracts/*.schema.json (copied verbatim from the cookbook)
```

Fetched files are cached under `pipeline/.cache/<repo>/<sha>/<path>` (git-ignored); delete it to refetch. A full catalog run fetches ≈ 250 guide files + 88 media files + 34 metadata files (≈ 120 MB) and takes about a minute warm, a few minutes cold.

## What is pinned (C-01)

`pipeline/sources.json` pins the five FIA repos and the 29 Aquifer Bibles used by FIA languages to a 40-hex commit SHA, resolved with `git ls-remote` on 2026-09-30 (the GitHub REST API was not reachable from the build session). Every fetch goes to `raw.githubusercontent.com/BibleAquifer/<repo>/<sha>/<path>` — never `main`. Every pack records `sourceRevisions` (repo → sha) and every file's `sha256` + `bytes`; every catalog entry records `sourceRevision` = sha256 of its `sourceRevisions` map. The MCP `browse` tool fails on the large English files, so the pipeline reads `<lang>/metadata.json` + `<lang>/json/NN.content.json` directly, as the PoC did.

## Layout

| Path | Contract | What |
|---|---|---|
| `sources.json` | C-01 | repo pins + languages + Bible editions per language |
| `src/lib.mjs` | — | pinned fetch + cache, sha256, USFM/BBBCCCVVV helpers, guide HTML → steps/units (ported from the PoC `content-lib.mjs`), pause detection |
| `src/inventory.mjs` | C-03 | languages × pericopes × resource types; presence, counts, byte estimates, `ai`/`absent` slots |
| `src/pericope.mjs` | C-02, C-04, C-05, C-06, C-08 | one pack: guide units (`S0n-Unnn`, stops), Scripture editions, key terms/images/maps/videos by passage overlap, derivative slots |
| `src/rights.mjs` | C-13 | one record per repo; `license_info` and `adaptation_notice` verbatim; discrepancies preserved |
| `bin/*.mjs` | — | CLIs |
| `test/contracts.test.mjs` | all | ajv validation + invariants |
| `../data/catalog/` | C-03 | `manifest.json` (strict C-03), `<lang>.json` (detail: per pericope `sourceId`, `engSourceId`, `indexReference`, per-resource slots), `COVERAGE.md` |
| `../data/packs/<lang>.<pericope>/` | C-02… | five proof packs (text tier only) |
| `../data/rights/` | C-13 | `records.json`, `NOTICE.md` |

Pericope ids follow M14's default: USFM book + range (`MRK-1-1-13`; cross-chapter `GEN-1-1-2-3`), with the Aquifer article id kept as `sourceId` (and `engSourceId`) in the detail files and packs.

## Slots and the fallback ladder (R-305)

Per (language, pericope) each resource is `source` (the language's own Aquifer content), `absent` with `fallback: "eng"` and `ai: true` + `generator` (translation / narration / description — a backfill slot, generated later and always marked), or `absent` with `ai: false` and `badge: "not-yet-in-language"` (maps for non-English; Scripture where the language has no edition — English editions are attached as `absent-fallback`, never generated). Guide narration is `ai: true, generator: narration` everywhere (Aquifer has no guide audio); `narration.json` (C-05) ships empty and `narration-plan.json` lists every clip slot with its `sourceSha256`.

## Known limits

- **Byte tiers are estimates.** `tierBytes.text` sums real guide bytes + real key-term text bytes + verses × 160 B per edition; phone/medium/original apply the CONSTRAINTS § 1.5 sample sizes (image 114 KB, map 6.6 MB, term audio 1.45 MB) and per-unit narration guesses. No media is fetched or transcoded here; C-08 descriptors in packs are slots (`status: pending-transcode`, zero sha) until lane L4/the media job fills them.
- **Guide units per pericope in the catalog are estimated** (bytes ÷ 260); the pack carries exact counts. Unit split includes `<h3>/<h4>` as `heading` units, so counts differ from the PoC (117 for eng Mark 1 with `<p>|<li>` only).
- **Pause/stop detection is a keyword net** (English, Spanish, French, Portuguese, Indonesian, Swahili, Tok Pisin, Russian, Arabic, Hindi, Chinese). It finds 24 stops in eng Mark 1 (PoC hand-curated 39) and only 1–2 in spa/arb/hau — localized wording escapes the net; L3 should treat `stops` as a floor and the PoC cue list as the reference for eng.
- **Term → unit attachment** is by localized title mention in the unit text (plus explicit `data-content-id` refs); passage association is pericope-level. ACAI links are not used (confidence too low, CONSTRAINTS § 1.1).
- **Media localization** is title-only in Aquifer; the catalog marks a localized image/video when the English metadata lists that language.
- **Partial Bibles** (ULT/UST 29 of 32 FIA books, AFBRT 8, GLT/GST hin 29 / ind 6, OICNT 18) are probed per book with HEAD requests; whole Bibles (66 articles) are assumed to have every book.
- **Upstream data quirks recorded, not fixed:** `fra-mrk-p0-v2` has `index_reference: 00000000` and is skipped (listed under `skipped` in `data/catalog/fra.json`); `rus` key terms are 37 audio articles with no text articles on Aquifer; FIAMaps `license_info` holder is Biblica while its adaptation notice says Word Collective (both kept, `discrepancies` on the C-13 record; ask M5).
- **No Bible licence verification** beyond copying `license_info` verbatim; non-English Bible licences remain unverified (CONSTRAINTS § 2).
- Catalog detail files are ≈ 30 MB total (compact JSON); the strict C-03 `manifest.json` is 7.5 MB. Not yet gzipped or split for the app's always-cached tier (M1 ≤ 60 MB gz is met with room).
